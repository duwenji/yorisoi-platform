## 1. 関係者と呼び方

このシステムの関係者は、**散策者・チャンネル提供者・素材提供者**の 3 者と、3 者のあいだに立って審査と配信をする**運営**。

| 呼び方 | だれか | 何をするか | 何を得るか | コード・契約上の名前 |
|---|---|---|---|---|
| **散策者** | アプリで散歩する人 | チャンネルを選び、切り替えて歩く。組み込みのチャンネルは自分好みに変える。AI を呼ぶ量の上限を決める。問題のある発言・チャンネルを知らせる | 同じ道でも違う散歩の体験 | `user`（画面・文書では散策者） |
| **チャンネル提供者** | 観光協会・店舗・愛好会など | 語り手・話題・話す場面・頻度、使う素材集と素材を出すきっかけを決めたチャンネルを作り、申請する（演出） | 自分の視点で、散策者に土地を案内できる | `publisher`（アカウントID `sg1…`） |
| **素材提供者** | 観光協会・写真家・語り手など | テキスト・画像・音声・映像を素材集にまとめ、申請する。どのチャンネル提供者に使わせるか、AI の根拠に使わせるかを決める（根拠） | チャンネルを作らなくても、素材を散策者に届けられる。AI の語りの根拠になる | `producer`（アカウントはチャンネル提供者と共通） |
| **運営** | 当面は開発者本人（ADR-001 C-10） | 審査（枠に収まるかと演出の意図）・承認・通報への対応・取り下げ、身元の確認、鍵の管理。承認済みチャンネル・リストに署名して公開する（考査） | — | 管理システムの `operator` |

- 運営の中で働く人を指すときは「運営の担当者」と書く（例: 「審査を戻す（ほかの担当者に任せる）」）
- 運営が出す承認済みチャンネル・リストを、散策者から見た単位として**リスト**と呼ぶ。散策者は URL と**リストID**（`sc1…`。ルート鍵の指紋）でリストを足す。リストは関係者ではなく、運営が出すもの。API-002 の `provider` にあたり、役割として言うときは「リストの発行元」と書く
- リストは複数あってよい（内蔵のリスト、散策者が足したリスト、開発用のリスト）。ルート鍵を入れ替えると、リストIDが変わり別のリストになる
- アプリには、アプリ自身が持つ組み込みのチャンネルと、組み込みの素材（Wikimedia の写真、背景音、雰囲気の絵、定型文）もある。これらは運営の審査を通らず、アプリの版として届く。組み込みのチャンネルにも、第三者と同じ機械の確認・AI の一次審査・話させた見本を CI で回す（ADR-004 H-13）
- コード・JSON の項目名・API の名前は変えない（`publisher`・`producer`・`provider` のまま）

### 役割の分け方

散策の語りは、次の 5 つの役割で分ける（ADR-004 H-1）。生成AI は関係者ではなく、その場で話す**実演**の層。

| 役割 | 受け持つもの | 何を決めるか |
|---|---|---|
| 根拠 | 素材提供者 | 何を事実として話してよいか（審査済みの素材。AI の根拠に使ってよいと許したもの） |
| 演出 | チャンネル提供者 | だれが・何について・どれだけ・どの素材集で話すか |
| 実演 | 生成AI | 根拠と演出と枠の範囲で、その場で話す。事前には審査できない |
| 枠 | アプリ | どのチャンネルでも外れない決まり（止められない出来事、共通の指示、上限、AI の出力の確認） |
| 考査 | 運営 | 事前に枠と演出の意図を確かめ、事後に通報を受けて直させる・取り下げる |

問題が起きたときに直す人は、原因で決まる（ADR-004 H-7）。演出が原因ならチャンネル提供者、根拠が原因なら素材提供者、枠をすり抜けた AI の発言ならアプリ（開発者）。散策者には、AI の発言に誤りがありうることを示す。

## 2. チャンネルという考え方

チャンネルは、**同じ散歩を違う体験に切り替えるもの**。ラジオやテレビの局のように、散歩の途中でも切り替えられる（コード上の名前 `Station` はこのたとえから）。

- チャンネルが決めるもの: 語り手（人格・口調）、話題、話す場面、話す量、解説の長さ、優先するスポットの種類、トーン、背景音。第三者のチャンネルは、きっかけ（スポット・地点・出来事）と見せ方を決めて素材を出せる
- チャンネルが決められないもの（アプリが必ず守らせる）: 天気の急変・日の入り・施設の案内、AI への共通の指示（`shared/guard`。個人情報を尋ねない、勧誘しない、危険な場所に誘わない など）、見せ方の安全の決まり（歩いている間は全画面を開かない など）、取得の時期と量の上限

```mermaid
flowchart LR
  subgraph PROVIDERS["作る人"]
    CP["チャンネル提供者<br/>チャンネルを作る"]
    MP["素材提供者<br/>素材集を作る"]
  end
  subgraph OPS["運営（yorisoi-console）"]
    Review["機械の確認 → AI の一次審査 → 人の審査<br/>（身元の確認・AI の見本）"]
    List["承認済みチャンネル・リスト<br/>運営の鍵で署名"]
  end
  subgraph APP["アプリ（SanpoGuide）"]
    BuiltIn["組み込みのチャンネル・素材<br/>アプリの版として届く"]
    Check["署名・ハッシュを確かめて取り込む<br/>枠を強制"]
    AI["生成AI（実演）<br/>根拠と演出で、その場で話す"]
  end
  Walker["散策者<br/>選ぶ・切り替える・歩く"]
  CP -- "申請（署名つき）" --> Review
  MP -- "申請（署名つき）" --> Review

```

| | 組み込みのチャンネル | 第三者のチャンネル |
|---|---|---|
| 作る人 | アプリの開発者 | チャンネル提供者（素材は素材提供者も） |
| 届き方 | アプリの版 | 運営が出すリスト（[API-002](channel-list-api.md)） |
| 確かめ方 | 起動時に `StationValidator`（誤りなら起動しない）。CI で機械の確認・AI の一次審査・見本（ADR-004 H-13） | 運営の審査と署名、チャンネル提供者の署名、SHA-256、`StationValidator` |
| 散策者が変えられるか | 頻度・場面・解説の長さ・優先する話題・トーン・背景音 | 変えられない（使う・使わないだけ） |
| AI の費用 | 散策者の API キー。量の上限は散策者が決める | 散策者の API キー。頻度と解説の長さはチャンネル提供者が決め、散策者が決めた上限の中で動く（ADR-004 H-9） |

## 3. 関係者ごとの流れ

| 関係者 | 始める | 作る・選ぶ | 確かめる | 続ける・やめる |
|---|---|---|---|---|
| 散策者 | アプリを入れる。第三者のチャンネルはリストを足す | チャンネルを取り込み、選ぶ。AI の上限を決める | 問題のある発言・チャンネルを知らせる | 新しい版は自動で取り込む。取り下げは理由とともに知らされる |
| チャンネル提供者 | 管理システムに登録し、鍵を紐づける | パッケージを作り、署名して申請する | 機械の確認、試用チケット、審査 | 版を上げて申請し直す。鍵の移し替え、退会 |
| 素材提供者 | 同じアカウントで「素材提供者として始める」 | 素材集を作り、署名して申請する | 機械の確認（外部の素材も）、身元の確認 | 使っているチャンネルの確認、毎日の確認、退会 |
| 運営 | ルート鍵と署名鍵を用意する | — | 審査・承認・差し戻し、通報への対応・取り下げ | 毎日のリストの作り直し、鍵の入れ替え |

## 4. 関係者ごとの課題と対応案

番号は課題の ID。

### 4.1 散策者

| ID | 課題 | 根拠 | 対応案 |
|---|---|---|---|
| W-1 | 第三者のチャンネルを見つけられない。リストの URL とリストID を手で入れる必要があり、内蔵のリストはまだない | `ChannelsScreen`「リストはまだありません」 | 管理システムの本番の準備を先にし、本番のリストを内蔵する。それまでは QR コード・リンクでリストを足せるようにする |
| W-2 | 選ぶための情報が少ない。一覧に出るのは名前・概要・チャンネル提供者・版だけで、リストにある説明・タグ・地域・アイコンを出していない | `ChannelsScreen.ChannelRow` | チャンネルの詳細の画面（説明・アイコン・素材の有無と素材提供者）。今いる地域に合うものを上に並べる |
| W-3 | AI の費用が増えるかどうか分からない（散策者の API キーで、チャンネル提供者が決めた頻度・長さで話す） | ADR-001「費用」 | 決定（ADR-004 H-9）: 散策者が AI を呼ぶ量の上限を決め、頻度と長さはその中で動く。取り込む前に、そのチャンネルの頻度と長さでの目安を出す |
| W-4 | 問題のあるチャンネルを知らせる手段がない | 審査基準 未決事項 No.3 | 決定（ADR-004 H-11）: 発言ごと・チャンネルごとに知らせる入口を置き、事後の対応を審査の柱にする。知らせ方はメールの下書きで、宛先はリストの運営（案内文書の `contact`）。組み込みのチャンネルはアプリの問い合わせ先 |
| W-5 | 素材提供者の「確認済み」の印が未定 | ADR-002 未決事項 No.4 | 第三者の公開の前に決める |

### 4.2 チャンネル提供者

| ID | 課題 | 対応案 |
|---|---|---|
| C-1 | 反応が分からない（何人が取り込んだか） | 公開 URL（CloudFront）の記録から、パッケージの取得数を日別・概数で集計し、画面に出す。アプリは変えず、散策者を特定しない |
| C-2 | 作る敷居が高い。JSON とプロンプトを手で書いて ZIP にする。AI の見本は運営しか見られず、試用には開発者モードが要る | ①ひな形の ZIP、②申請の前に自分の API キーで AI の見本と AI の一次審査を使う（②は決定。ADR-004 H-12）、③画面のフォームで作る（次の段階） |
| C-3 | 使える素材集を探せない（公開中の素材集の一覧がない） | 自分が使ってよい（`grants`）素材集を、タグ・地域で探せる一覧 |
| C-4 | 審査にかかる期間、異議の申し立て、審査の費用が未定 | 公開の前に決める（審査基準 未決事項 No.1・2） |
| C-5 | 素材集の更新で中身が変わり、チャンネルの意図とずれる | ADR-002 のリスク。チャンネルから素材集の版を固定できるようにするか検討する |

### 4.3 素材提供者

| ID | 課題 | 対応案 |
|---|---|---|
| M-1 | 想定する素材（観光協会の音声ガイドなど）がまだ届かない。アプリが出せるのは文字と画像（第 1 段）まで | 音声（第 2 段）の時期を TODO に書く。素材提供者ガイドの冒頭に「今届くのは文字と画像」と書く |
| M-2 | チャンネル提供者と出会う場がない | C-3 の一覧が両者の出会いの場になる。組み込みのチャンネルが基準（タグ）で素材集を使う道も検討する |
| M-3 | 反応が分からない | C-1 と同じ集計を素材集ごとにも出す |
| M-4 | 権利の申し立ての窓口と「確認済み」の印が未定 | ADR-002 未決事項 No.4・5。W-4 と同じ窓口で受ける |
| M-5 | 素材のテキストが AI の解説の根拠に使われない | 決定（ADR-004 H-3〜H-5）: 素材提供者が許した素材集（`grants.grounding`）を、題材が一致するときに AI の根拠として渡す（API-004「AI の根拠」） |

### 4.4 運営

| ID | 課題 | 対応案 |
|---|---|---|
| O-1 | 担当者が 1 人で、審査・身元の確認・取り下げ・窓口をすべて受け持つ | 決定（ADR-004 H-10〜H-12）: 事前の審査は枠と演出の意図に絞り、AI の一次審査で補う。事後の対応を柱にする。審査期間の目安（C-4）は担当者 1 人で回せる値にし、W-4・M-4 の窓口は 1 つにまとめる |
