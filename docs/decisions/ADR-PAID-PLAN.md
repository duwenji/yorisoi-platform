## 目的・背景

[提供価値と事業の検討](../overview/value-proposition.md#p-1-の料金の案) の P-1 の料金の案は承認済みです。たっぷりプランは月 980 円・1 日 200 回、無料は 20 回で、どちらも DeepSeek V3.2 です。値段と上限は後から変えます。

作る前に、[TODO](../TODO.md)「有料プラン（P-1）」の次の 4 つを決めます。

1. プランごとの上限の持ち方（API-AI-RELAY R-2・R-14 の改訂）
2. 購入の確かめ方と、回数を数える単位
3. SanpoGuide と CycleGuide で定期購入を分けるか
4. Play Console で確かめること

料金を取り始めるのは、H-1（続けて使われるか）を確かめてからです。本書は、そのときにすぐ作れるよう、先に決めておくためのものです。

## スコープ・非スコープ

スコープ:
- 中継の上限の設定、購入の確かめ方、回数の数え方、残すもの
- アプリと中継の間の API の変更（案）
- 定期購入の商品の分け方

非スコープ:
- アプリの画面の作り（各アプリの文書）
- 値段そのもの（value-proposition で承認済み）
- 自分のキーの経路（R-3 のまま。プランと関係しない）

## 決定（案）

### 上限の持ち方

| ID | 決定 | 理由 |
|---|---|---|
| D-1 | 中継の設定に、無料の上限 `daily-limit` と、たっぷりプランの上限 `daily-limit-plus` を別に持つ。どちらも 5〜300 の整数で、運営が Parameter Store で変え、配備し直さずに 5 分で効く（R-14 と同じ）。正しくない値のときは、無料は 100 回・たっぷりプランは 200 回で動かし、運営に知らせる | 値段と上限を後から変えられるようにする（value-proposition「後から変えるもの」）。300 まで許すと、200 から上げる余地が残る |
| D-2 | 無料の上限を 20 回に下げるのは、たっぷりプランを売り始めるときにする。それまでは今の 100 回のまま | 払って広げる道がないうちに下げると、利用者が困るだけになる |
| D-3 | 準備役の枠は、今と同じく上限の 2 割（AGENT A-33）。たっぷりプランでは 40 回 | 上限と一緒に変わる。別の設定を増やさない |
| D-4 | 長さの上限（R-9）は変えない。1 日の費用の上限は、1 回の上限 × 1 日の回数で決まる。たっぷりプランで上限まで使っても 1 日約 0.26 ドル（0.00128 ドル × 200）で、長さの上限いっぱいに使っても 1 日約 2.5 ドル。全体は月の予算（R-10）で止まる | 1 回の長さは用途で決まり、プランで変える理由がない |

### 購入の確かめ方と回数の単位

| ID | 決定 | 理由 |
|---|---|---|
| D-5 | アプリは Google Play の課金ライブラリで購入し、購入トークンを中継の新しい `POST /v1/plan` に送る。中継は Google Play Developer API（`purchases.subscriptionsv2.get`）でトークンを確かめる。確かめるのは、パッケージ名がセッションのアプリと同じこと、商品 ID が中継の設定の一覧にあること、状態が有効（`ACTIVE`）か猶予期間（`IN_GRACE_PERIOD`）であること、期限（`expiryTime`）の 3 点。まだ承認されていない購入は、中継が承認（acknowledge）する | アプリの言うことだけで上限を広げない。承認を中継がすれば、中継が確かめた購入だけが残る（3 日以内に承認しないと Play が返金する） |
| D-6 | たっぷりプランの回数は、**定期購入ごと**に数える（購入トークンのハッシュ `QUOTA#P-{hash}` / `DAY#{日付}`）。同じ Google アカウントの 2 台の端末で使えば、200 回を 2 台で分ける。無料の回数は今と同じくインストール ID ごと | 1 つの購入を多くの端末で使い回して、上限を何倍にもさせない。入れ直しても、購入を戻せば同じ残りになる |
| D-7 | その日の途中でたっぷりプランになったときは、たっぷりプランの残りは 200 回から始める。その日に無料で使った回数は足さない | 数え方を単純にする。差は最大でも無料の上限の分 |
| D-8 | 中継は、確かめた購入の期限まで、それをたっぷりプランとして扱う。期限を過ぎたとき、または新しいセッション（24 時間ごと）を作るときに確かめ直す。最初は、リアルタイム デベロッパー通知（Pub/Sub）を受けない | 取り消し・返金は、遅くとも 24 時間で反映される。Pub/Sub を中継に通す構成と認証を、最初は作らずに済む。利用者が増えて返金の悪用が見えたら足す（U-3） |
| D-9 | 開発用の中継は、Play Console のライセンス テスターの購入（テスト用の購入）も受ける。本番の中継は受けない | 内部テストで、お金を払わずに確かめられる |
| D-10 | 中継が Google Play Developer API を呼ぶサービス アカウントは、配信に使うもの（`tools/play.mjs`）と分ける。権限は、購入の確認と承認に要るもの（「財務データの表示」と「注文と定期購入の管理」）だけにし、鍵は Secrets Manager に入れる | 配信の鍵が漏れても購入に触れず、購入の鍵が漏れても配信に触れない |

### API の変更（案）

`POST /v1/plan`（`Authorization: Bearer {token}`）:

```json
{ "purchaseToken": "…", "productId": "plus" }
```

```json
{
  "plan": { "name": "plus", "expiresAt": "2026-12-24T03:00:00Z" },
  "quota": { "limit": 200, "remaining": 200, "resetsAt": "2026-11-24T15:00:00Z" }
}
```

- 確かめられなかったときは `403 plan_not_active`（期限切れ・保留・取り消し）、`400 invalid_request`（知らない商品 ID、別のアプリのトークン）を返し、無料のまま続ける
- `GET /v1/quota` と `POST /v1/session`・`/v1/generate`・`/v1/agent` の `quota` に、`plan`（`free` か `plus`）を足す。アプリは上限の値と同じく、プランも中継の返す値に従う
- Google Play Developer API が失敗したときは `502 upstream_error`。前に確かめた購入が期限内なら、たっぷりプランのまま続ける
- 追加だけで、今のアプリはそのまま動く（`plan` を読まなければ無料のまま）

### 商品の分け方

| ID | 決定 | 理由 |
|---|---|---|
| D-11 | 定期購入は**アプリごとに別**にする。SanpoGuide と CycleGuide に、それぞれ商品 `plus`（基本プランは月払い `monthly` と年払い `yearly`）を置く | Play の定期購入はアプリ（パッケージ）ごとで、別のアプリの購入を確かめるには、利用者のアカウントを運営が持つ必要がある。yorisoi はアカウントを作らない |
| D-12 | 先に売るのは SanpoGuide だけ。CycleGuide は、SanpoGuide で H-9 の払う割合が見えてから決める | 運営は当面 1 人。1 つのアプリで確かめてから広げる |

### 残すもの

| ID | 決定 | 理由 |
|---|---|---|
| D-13 | 中継が残すのは、購入トークンのハッシュ・パッケージ名・商品 ID・期限・最後に確かめた時刻だけ。Google アカウントや注文 ID は残さない。期限から 30 日で消す。日ごとの回数の分布（R-13）は、無料とたっぷりプランで分けて残す | 回数の単位と、確かめ直しに要るものだけにする。分布をプランで分ければ、たっぷりプランの値段と上限を見直せる |

## 比べた案

| 論点 | 採る案 | 採らない案 | 採らない理由 |
|---|---|---|---|
| 回数の単位（D-6） | 定期購入ごと | インストール ID ごと | 1 つの購入を何台にも入れれば、上限が台数倍になる |
| 取り消しの反映（D-8） | 期限とセッションで確かめ直す | 最初からリアルタイム デベロッパー通知 | Pub/Sub の受け口と認証が要る。24 時間の遅れで困る量ではない |
| 商品（D-11） | アプリごと | 2 つのアプリで共通の購入 | 利用者のアカウントが要る |
| 決済（value-proposition） | Play の決済 | 外の決済サイトへの案内 | 手数料の差 5% が、決済の会社の手数料と手間で相殺される |

## 未決事項

| No. | 事項 | 決め方 |
|---|---|---|
| U-1 | Play Console で、年の売上 100 万ドルまでの 10% に登録が要るか。Google のヘルプには書かれていない（2021 年の 15% は、「関連するデベロッパー アカウント」の画面で登録が要った） | 開発者が Play Console の「関連するデベロッパー アカウント」・手数料の画面を見る。分からなければ Play のサポートに聞く |
| U-2 | 値上げのしかた。日本では、同意を求めずに知らせるだけの値上げ（opt-out）が使える。条件は、30 日前に知らせる、基本プランごとに 1 年に 1 回まで、上げ幅は今の値段の 50% か 1 日 17 セントの大きいほうまで | 値上げするときに決める。アプリに、値上げを知らせる画面が要る |
| U-3 | リアルタイム デベロッパー通知を足すか | 返金の悪用が見えたとき |
