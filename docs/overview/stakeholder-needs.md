# 関係者の課題と対応案

| 項目 | 内容 |
|---|---|
| 対象 | yorisoi の関係者が挙げた課題、対応案、未解決事項 |
| 読む人 | アプリ開発者、チャンネル提供者、素材提供者、運営 |
| 状態 | 課題の記録。対応案は ADR/API で決定済みと明示したものを除き、未承認 |
| 関連 | [関係者と共通用語](roles-and-vocabulary.md)、[エコシステム TODO](../work/ecosystem-todo.md) |

このページは課題と検討履歴を残すもので、ここに書かれた対応案だけでは仕様になりません。「決定済み」は参照先の ADR・API 契約に従います。現在の実装状況や未完了項目は [エコシステム TODO](../work/ecosystem-todo.md) および各リポジトリの TODO を確認してください。

## アプリ利用者

| ID | 課題 | 根拠 | 対応・状態 |
|---|---|---|---|
| W-1 | 第三者のチャンネルを見つけにくい。リストの URL とリストID を手で入力し、内蔵リストがない状態だった | SanpoGuide の `ChannelsScreen` に「リストはまだありません」と表示された | 対応案は本番管理システム・内蔵リスト・QR／リンクで追加すること。SanpoGuide の現状はアプリ別手引きと TODO を確認 |
| W-2 | 選ぶための情報が少ない。名前・概要・提供者・版以外の説明、タグ、地域、アイコンなどが一覧にない | SanpoGuide の `ChannelsScreen.ChannelRow` | 提案: 詳細画面と地域に応じた並べ替えを用意する |
| W-3 | チャンネル提供者が頻度や長さを決めるため、AI の費用が増えるか分かりにくい | チャンネルと利用者で費用決定・負担者が異なる | **決定済み**: 利用者が AI の呼び出し量の上限を決める（ADR-AI-ROLES H-9）。取り込み前に費用の目安を示す設計も同項を参照 |
| W-4 | 問題のあるチャンネルや発言を知らせる手段が必要 | 審査基準の旧未決事項 No.3 | **決定済み**: 発言・チャンネル単位の通報入口を置き、事後対応を柱にする（ADR-AI-ROLES H-11）。宛先等の現行手順は SanpoGuide 手引きと審査基準を参照 |
| W-5 | 素材提供者の「確認済み」表示の扱いが未定 | ADR-MATERIAL-PRODUCERS 未決事項 No.4 | 未決。公開前に判断する |

## チャンネル提供者

| ID | 課題 | 根拠 | 対応・状態 |
|---|---|---|---|
| C-1 | チャンネルを何人が取り込んだか分からない | 配信の反応を把握しにくい | 提案: 公開 URL の記録から取得数を日別・概数で集計し、利用者を特定せず表示する |
| C-2 | JSON・プロンプト・ZIP を手で用意する必要があり、作成の敷居が高い | 申請前に AI の見本を確認する手段も必要 | ①ひな形、③フォームは提案。②申請前の AI 見本・AI 一次審査は**決定済み**（ADR-AI-ROLES H-12） |
| C-3 | 利用可能な素材集を探しにくい | 公開中の素材集を見つける一覧がない | 提案: `grants` で利用できる素材集をタグ・地域から探せる一覧を用意する |
| C-4 | 審査期間、異議申し立て、審査費用が分からない | 申請時の見通しが必要 | **決定済み**: 審査無料、機械確認合格後 5 日を目安とする（ADR-CHANNEL-CURATION C-14）。異議申し立ては審査基準の未決事項を参照 |
| C-5 | 素材集の更新で中身が変わり、チャンネルの意図とずれる | 素材集の版とチャンネルの依存関係 | 検討事項: チャンネルから素材集の版を固定できるか（ADR-MATERIAL-PRODUCERS のリスクを参照） |

## 素材提供者

| ID | 課題 | 根拠 | 対応・状態 |
|---|---|---|---|
| M-1 | 期待される音声ガイド等がアプリに届かず、当初は文字・画像しか使えない | SanpoGuide の機能段階 | アプリが提供できる素材の種類と対応時期はアプリ別手引き・TODOで管理する |
| M-2 | チャンネル提供者と出会う場がない | 素材集を利用するチャンネル提供者を見つけにくい | 提案: 素材集一覧を両者の出会いの場にする。組み込みチャンネルからの基準選択も検討する |
| M-3 | 素材集を利用した反応が分からない | 利用実績を確認できない | 提案: C-1 の集計を素材集にも提供する |
| M-4 | 権利申し立ての窓口と「確認済み」表示が未定 | 権利者が申し立てる手段が必要 | 窓口は**決定済み**（ADR-MATERIAL-PRODUCERS D-21、審査基準）: リストの運営の連絡先でメール受付。「確認済み」表示は未決 |
| M-5 | 素材のテキストが AI の解説の根拠に使われない | 素材提供者が提供する事実情報を活用したい | **決定済み**: 素材提供者が許可した素材を、題材が合うとき AI の根拠として渡す（ADR-AI-ROLES H-3〜H-5、API-004） |

## 運営

| ID | 課題 | 根拠 | 対応・状態 |
|---|---|---|---|
| O-1 | 少人数の担当者が審査、本人確認、取り下げ、問い合わせを担い、負荷が高い | 運営は当面 1 人（ADR-CHANNEL-CURATION C-10） | **方針決定済み**: 事前審査を枠と演出の意図に絞り、AI の一次審査で補助し、事後対応を柱にする（ADR-AI-ROLES H-10〜H-12）。審査期間の目安は ADR-CHANNEL-CURATION C-14 を参照 |

## 過去の進め方の整理

元文書にあった段階案は、関係者の課題に対する検討時点の並べ方です。現行の優先順位や実施状況を表すものではありません。

| 順 | 検討時点の案 | 関連 ID |
|---|---|---|
| 1 | 関係者の呼び方を文書・画面でそろえ、「チャンネルという考え方」を構造図に加える | — |
| 2 | 公開前に本番・内蔵リスト、通報窓口、審査期間・費用を整える | W-1・W-4・M-4・C-4・O-1 |
| 3 | 公開直後にチャンネル詳細、取得数、素材集一覧を用意する | W-2・W-3・C-1・M-3・C-3・M-2 |
| 4 | その後にフォーム作成と素材集の版固定を検討する。素材を AI の根拠にする決定は ADR-AI-ROLES T-3・T-4 に記録 | C-2・M-5・C-5 |

## 元文書から分けて扱った内容

- 元文書の「関係者ごとの流れ」は、SanpoGuide の画面・yorisoi-console の操作に結び付いた具体的な手順です。共通用語のページには移さず、アプリ側の操作は[SanpoGuide 手引き](../apps/sanpoguide/manual/README.md)、管理システム側の操作は [yorisoi-console の利用ガイド](https://github.com/duwenji/yorisoi-console/blob/main/docs/guide/README.md)を参照してください。
- 元文書の「同じ散歩を違う体験に切り替える」という比喩とコード名 `Station` は SanpoGuide の散策体験・実装に固有の説明です。共通のチャンネル定義は[関係者と共通用語](roles-and-vocabulary.md)と API 契約に整理しました。
- 元文書にあった Mermaid の関係者フロー図と、組み込み・第三者チャンネルの機能比較は SanpoGuide の機能・画面を前提にするため、共通文書には複製していません。現在のアプリでの動きは[SanpoGuide 手引き](../apps/sanpoguide/manual/README.md)を参照してください。
