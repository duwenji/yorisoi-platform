## 目的・背景

雑談（[REQ-NEARBY-TALK](REQ-NEARBY-TALK.md) F-14〜F-20）の AI に渡しているのは、日時と季節（春・夏・秋・冬）だけです。そのため、

1. 季節の話が「秋ですね」「涼しくなりましたね」の繰り返しになりやすい
2. AI が自分の知識で「もうすぐ立冬ですね」と話すと、日付を間違えることがある（AI-ROLES H-6 ① を守り切れない）

人が隣を歩いて話すときは、「今日は立冬ですね」「明日は十五夜だそうですよ」と、その日ならではの暦の話をします。本書は、アプリが暦の事実を計算して AI に渡し、雑談の話題の 1 つにする要件です。

あわせて、実機で季節の歌が一度も流れなかった問題（下の「季節の歌の直し」）を直します。暦で雑談の話題が 1 つ増えると、歌の番がさらに遠くなるためです。

## スコープ・非スコープ

### スコープ
- 暦の事実を計算し、表から引く部品（platform `kit-calendar`、新規）
- 雑談の話題「暦」と、話す事実の選び方（両アプリ）
- 暦を話すときの話し方の決まり（プロンプトの固定部分）
- チャンネルからの制御: `talk.events.calendar`、`calendar.prefer`・`calendar.skip`（core-format の語彙、API-CHANNEL-PACKAGE、yorisoi-console の確認の仕組みとエディタ）
- 組み込みのチャンネル（SanpoGuide 6 つ・CycleGuide 3 つ）の暦の設定の見直し
- 季節の歌の直し（両アプリ。F-40〜F-44）

### 非スコープ
- 暦の配信（運営の配信から暦を取ること。D-2）
- 散歩の始まり・区切りなど、雑談以外の話しかけで暦に触れること（U-2）
- アプリ利用者が暦の種類を選ぶ設定（U-1）
- チャンネルが独自の暦（寺の縁日・地域の祭りなど）を持つこと、日付で動くきっかけ（自治体の公開データの催しは [REQ-LOCAL-EVENTS](REQ-LOCAL-EVENTS.md)）
- 商品・お店のための記念日（D-5）
- 画面に暦を出すこと（話すだけ）
- iOS

## 方針・決定事項

| No. | 決定 | 理由 |
|---|---|---|
| D-1 | 暦はアプリの中で計算する。二十四節気・雑節は太陽の視黄経から、月の満ち欠けと旧暦（六曜・十五夜・十三夜のもと）は月と太陽の黄経の差から計算する。天文の計算には公開ライブラリ Astronomy Engine（MIT ライセンス、`io.github.cosinekitty:astronomy:2.1.19`。VSOP87 と NOVAS をもとにし、誤差は 1 分ほど）を使う。Maven Central にないので JitPack から取り、JitPack から取るのはこのライブラリだけに絞る（Gradle の `exclusiveContent`）。日付の区切りは日本時間（2026-11-15 改訂） | 開発者の決定（2026-11-15）。通信が要らず、配信も更新も要らない。圏外の散歩でも使える。Meeus の簡単な式は誤差が 0.01°（時刻で 15 分ほど）あり、真夜中の前後の節気の日付がずれるおそれがある。取り込み方は、源コードを写す案より、依存として取る案を開発者が選んだ（2026-11-15） |
| D-2 | 計算の正しさは、公開済みの国立天文台の暦要項のうち 2016〜2027 年の 12 年分の値とテストで照らして確かめる。照らす値は暦要項の PDF から写してテスト用の表にし、写した版を書いておく。食い違う年は、部品の中の上書きの表で直す（2026-11-15 改訂） | 節気や朔（新月）が日本時間の真夜中のすぐ前後に当たる年は、計算の小さな誤差で日付が 1 日ずれることがある。暦要項は毎年 2 月に翌年分が出るだけで、2028 年より先の値はない。計算式は年で変わらないので、過去 12 年と一致すれば先の年にも通じるとみなす |
| D-3 | 暦の事実の種類は 10 個（下の「暦の種類」）。どの事実にも「確かさの種類」と、運営が書いた 1 行の説明を持たせる | AI が説明にない由来を作らないようにする。確かさの種類ごとに話し方を変える（D-7） |
| D-4 | 六曜は入れる。言い伝えとして話し、六曜を理由に何かを勧めたり避けさせたりしない。吉凶を占う口調にしない | 開発者の決定（2026-11-15）。暦注として広く知られた事実ではあるが、迷信として差別や偏見につながると人権啓発で取り上げられることがある。チャンネルが外せるようにする（D-9） |
| D-5 | 記念日は、国・自治体・業界団体・公益団体が定めたものだけを運営が選んで表にする。会社が自社の商品・店のために定めたもの（商品名・社名の付いたもの）は入れない。各日に、定めた団体・由来・確かめた資料を持たせる。由来の文は運営が書く（資料の文を写さない） | 語りに宣伝が混ざらないようにする（AI-ROLES H-16）。だれが定めたかを添えて話せるようにする（D-7） |
| D-6 | 地域ごとに違う行事（お盆の時期・地蔵盆・十日夜と亥の子など）は、行う地域を持たせて表にする。利用者が今いる地域は、市区町村まで、端末の中で決める（運営が配る市区町村の代表点の表。外のジオコーディングのサービスは使わない。[AGENT](../overview/agent.md) A-14）。座標は外に出さない | 地域を添えて話せば、利用者の地域が分からなくても誤りにならない。市区町村は端末の中で決めるので、位置は外に出ない |
| D-7 | 話し方は、確かさの種類ごとにプロンプトの固定部分で決める（F-17）。チャンネルのスロットでは変えられない | 六曜・記念日・地域の行事は、言い方を誤ると、事実でないことを事実として話すことや宣伝になりかねない。チャンネルごとに違えてよいことではない |
| D-8 | 話す暦の事実は、アプリが 1 つ選んで AI に渡す。AI には選ばせない | REQ-NEARBY-TALK D-8 と同じ。渡す量を一定にし、同じ散歩で同じ事実を繰り返さない |
| D-9 | チャンネルは、暦を使うか（`talk.events.calendar`）、外す種類（`calendar.skip`）、先にする種類（`calendar.prefer`）を決められる。準備役の暦（先に取る道具 `calendar`）にも同じ方針をかけ、`talk.events.calendar` が偽なら場面 `calendar` を使わない（AGENT A-7） | 開発者の決定（2026-11-15）。何について話すかは演出で、チャンネルの受け持ち（AI-ROLES H-1、MATERIALS D-37）。教えとして日の吉凶を選ばない宗派の寺のチャンネルが六曜を外す、自然のチャンネルが七十二候を先にする、などに応える |
| D-10 | 暦は素材ではない。天気やスポットの情報と同じく、アプリが AI に渡す「今の状況」として扱う | 素材提供者はおらず、AI を通さずにそのまま見せるものもない（MATERIALS D-2）。表の中身（記念日・地域の行事の説明）は、アプリの固定部分としてアプリ開発者が受け持つ（AI-ROLES H-7） |
| D-11 | 暦は雑談の話題の 1 つなので、AI が使えるときだけ話す。定型の文は作らない | REQ-NEARBY-TALK D-9 と同じ |
| D-12 | 季節の歌の直しを本書に入れる | 開発者の決定（2026-11-15）。暦で話題が増えると、歌の番がさらに遠くなる |
| D-13 | 調べた話の筋で話した・話す予定の暦の事実は、その日の暦の話題から外す（[AGENT](../overview/agent.md) A-40） | 同じ暦を 2 度話さない |

## 機能要件

### 暦の部品（platform kit-calendar）
| ID | 要件 |
|---|---|
| F-1 | `kit-calendar` は Android に依存しない Kotlin/JVM の部品にする。日付（日本時間）を渡すと、その日に話せる暦の事実（`KoyomiFact`）の一覧を返す |
| F-2 | `KoyomiFact` は、`id`（種類・名前・年を含む。例: `sekki:rittou:2026`）、種類（「暦の種類」の値）、名前、読み（あれば）、日付、今日との関係、説明（1 行）、確かさの種類、記念日なら定めた団体、地域ごとの行事なら行う地域、を持つ |
| F-3 | 今日との関係は次のどれか: 今日（その日）／〇日目（節気・七十二候の期間の中。入りの日を 1 日目とする）／あと〇日（1〜3 日）／昨日。事実ごとに、返すのはどの関係のときかを決める（F-4） |
| F-4 | 返す事実: ① 今の節気（入りの日からの日数つき）と、次の節気があと 1〜3 日なら次の節気も ② 今の七十二候 ③ 雑節・五節句と年中行事・旧暦の行事・祝日・地域ごとの行事のうち、今日・あと 1〜3 日・昨日のもの（土用・彼岸のように期間のあるものは期間の中なら毎日） ④ 新月・上弦・満月・下弦の前後 1 日 ⑤ 今日の記念日 ⑥ 今日の六曜 |
| F-5 | 計算は D-1 の方法で行い、国立天文台の暦要項の 2016〜2027 年の二十四節気・雑節・朔望・国民の祝日の日付と一致させる（D-2）。旧暦は、朔（新月）の日を月の始まりとし、中気を含まない月を閏月とする（天保暦の決まり） |
| F-6 | 記念日・地域ごとの行事・七十二候の名前と意味・各事実の説明は、部品に入れた表に持つ。表の各行は、記念日なら定めた団体と確かめた資料、地域ごとの行事なら行う地域と確かめた資料を必ず持つ |
| F-7 | 記念日の表の最初の版は、各月 2 件以上を目安にする。D-5 に当たらないものは入れない |
| F-8 | 1 日分の結果は、日付が変わるまで覚えておく（同じ日に何度も計算しない） |

### 雑談の話題「暦」（両アプリ）
| ID | 要件 |
|---|---|
| F-9 | 雑談の話題に「暦」を足す。順番は、季節と天気 → 時間帯 → 暦 → 歩いてきた道（走ってきた道）と距離 → 周りの見どころ → 体のこと → このチャンネルらしい話題 → 季節の歌（REQ-NEARBY-TALK F-15 を改める） |
| F-10 | 暦を話題に選べるのは、チャンネルが暦を使い（F-20）、その日の事実のうち、外す種類（F-21）を除き、今回の散歩・走行でまだ話していないものが 1 つ以上あるときだけ |
| F-11 | 話す事実はアプリが 1 つ選ぶ（D-8）。先にする種類（F-22）に入るものを先にし、その中では次の順にする（F-4 の番号とは別の順番）: 今日の行事・祝日・節気の入りの日・旧暦の行事 → あと 1〜3 日・昨日の行事 → 今の七十二候・今の節気 → 月の満ち欠け → 記念日 → 六曜。同じ順位なら、地域ごとの行事より全国共通のものを先にする |
| F-12 | 話した事実の `id` を、散歩・走行の間覚えておき、同じ散歩・走行では同じ事実を選ばない |
| F-13 | 雑談の AI には、ほかの雑談と同じ状況（今の話しかけと同じ）に加え、選んだ事実の名前・読み・日付・今日との関係・説明・確かさの種類（記念日なら定めた団体、地域ごとの行事なら行う地域）を渡す。長さは雑談と同じ（1〜2 文・80 字以内。CycleGuide は今の雑談の上限） |
| F-14 | 暦の雑談は AI が使えるときだけ話す（D-11）。AI が答えなかったときは、今の雑談と同じく黙り、その事実は話したことにしない |
| F-15 | 暦の雑談も、散歩・走行の記録（開発者モードの詳しい記録を含む）に、話題と事実の `id` とともに残す |
| F-16 | 暦の雑談は、雑談と同じ条件で出さない（頻度が「静か」、SanpoGuide でとどまっているとき、CycleGuide で信号の近く・速いとき。REQ-NEARBY-TALK F-18・F-19） |

### 話し方（プロンプトの固定部分。両アプリ）
| ID | 要件 |
|---|---|
| F-17 | 確かさの種類ごとに、次の話し方を頼む。**天文・法律**: 事実として言ってよい。**言い伝え**: 「昔の暦では」「〜と言われてきました」のように言い伝えとして話す。六曜では、何かを勧めたり避けさせたりせず、吉凶を占う口調にしない。**定めた人がいる**: 「〇〇（定めた団体）が定めた〇〇の日」と団体を添え、商品・お店を勧めない。**地域で違う**: 「〇〇の地域では」と地域を添え、利用者の住む地域を決めつけない |
| F-18 | すべての暦の雑談で、次を頼む: 触れる暦は 1 つだけ。知識を並べず、今の季節・天気・時間帯・見えているものと一言つなげる。渡した日付・名前・説明を言い換えない。説明にない由来・言い伝えを足さない |
| F-19 | 両アプリのプロンプトの版を上げ、プロンプトの正解ファイルと審査用の見本に、暦の雑談を足す。見本は、節気・六曜・記念日・地域ごとの行事・十五夜を 1 つずつ含める |

### チャンネルからの制御
| ID | 要件 |
|---|---|
| F-20 | `talk.events` に任意の `calendar`（暦）を足す。書かなければ真。`chat` が偽なら `calendar` も偽とみなす（`song` と同じ。REQ-NEARBY-TALK F-29） |
| F-21 | チャンネルの最上位に任意の `calendar` を足し、`skip`（外す種類。「暦の種類」の値の配列、0〜10 個）を書けるようにする。書いた種類の事実は選ばない |
| F-22 | `calendar.prefer`（先にする種類。同じ形）を書けるようにする。F-11 の選び方で先にする |
| F-23 | 同じ種類を `prefer` と `skip` の両方に書いたチャンネル、知らない種類を書いたチャンネルは、確かめる仕組みで拒む（core-format の `StationValidator`、yorisoi-console の確認の仕組み）。アプリは、知らない種類を無視する（古いアプリが新しい種類を受け取ったとき） |
| F-24 | 値は core-format のマイナー版で足し、`format` は上げない。F-20〜F-22 を使うチャンネルは、API-CHANNEL-LIST の必要な版で案内する |
| F-25 | yorisoi-console の画面のエディタで、F-20〜F-22 を選べるようにする。組み込みのチャンネルの値を見直す（例: 自然は `kou`・`sekki` を先にし `kinenbi` を外す。静かなチャンネルは `chat` が偽のまま） |

### 季節の歌の直し（両アプリ）
| ID | 要件 |
|---|---|
| F-40 | 曲の一覧と音を、端末にまだ 1 曲もないときは、アプリを起動したあと、取れる回線になりしだい取る（1 日 1 回の取り直しを待たない）。取る条件（回線は REQ-NEARBY-TALK F-33 の設定どおり、散歩・走行の最中でない）は変えない（REQ-NEARBY-TALK F-33・F-34） |
| F-41 | 設定の「季節の歌を流す」の下に、端末にある今の季節の曲の数を出す（「今の季節の曲: 4 曲」「まだ取っていません（Wi-Fi のときに取ります）」。モバイル通信でも取る設定のときは「まだ取っていません（通信できるときに取ります）」） |
| F-42 | 1 回の散歩・走行の 1 曲目は、話題の順番を待たない。歌を流せるとき（REQ-NEARBY-TALK F-23・F-26・F-27）は、次の雑談の話題を季節の歌にする。歩き始めて（走り始めて）からの時間は問わない。2 曲目は今までどおり話題の順番で選ぶ |
| F-43 | 季節の歌は、AI が使えないときも、定型の前置きで流す（REQ-NEARBY-TALK F-24 のとおり。今は雑談のルールが AI を条件にしているため、歌も流れない） |
| F-44 | チャンネルの出来事のアプリ利用者による変更（保存した `talk.events`）は、出来事ごとに真偽を残す。前の形（話す出来事の一覧だけ）で保存された変更を読むときは、一覧にない `preview`・`chat`・`song`・`calendar` を、チャンネルの値のままとみなす（今は偽とみなされ、雑談も歌も止まる） |

## 非機能要件

| ID | 要件 |
|---|---|
| N-1 | プライバシー: 暦のために外へ送るものはない（通信しない）。AI に渡す暦の事実は日付から決まるもので、位置を含まない |
| N-2 | 費用: 1 時間あたりの AI の呼び出しの上限（`AiCost.maxCallsPerHour`）は変えない。暦の雑談は雑談の 1 回として数える |
| N-3 | 性能: 1 日分の暦の計算は、端末で 50 ms 以内（F-8 で 1 日 1 回） |
| N-4 | 大きさ: `kit-calendar` の表（七十二候・記念日・地域ごとの行事・上書きの表）は合わせて 200 KB 以内 |
| N-5 | 期限: 計算に期限はない。毎年 2 月に翌年の暦要項が出たら、その年を照らす表に足す（2026-11-15 改訂） |

## 受入条件

1. AC-1（F-5、D-2）: 2016〜2027 年の二十四節気・雑節・朔望・国民の祝日・十五夜・十三夜の日付が、暦要項の値とすべて一致する（テスト）
2. AC-2（F-4）: 2026-11-15 に、立冬（9 日目）・今の七十二候・六曜が返り、2026-11-22 に小雪の入りの日が、2026-11-21 に「小雪まであと 1 日」が返る
3. AC-3（F-6・F-7・D-5）: 記念日の表のすべての行に定めた団体と確かめた資料があり、商品名・社名の付いた記念日がない。地域ごとの行事の表のすべての行に、行う地域と確かめた資料がある
4. AC-4（F-9〜F-12）: 普通の頻度で見どころのない道を 30 分歩く経路を流すと、暦の雑談が 1 回以上出る。同じ散歩で同じ事実が 2 回出ない
5. AC-5（F-21・F-22）: `calendar.skip` に `rokuyou` を書いたチャンネルでは六曜が選ばれず、`calendar.prefer` に `kou` を書いたチャンネルでは七十二候が先に選ばれる
6. AC-6（F-20）: `talk.events.calendar` か `chat` が偽のチャンネルでは、暦の雑談が出ない
7. AC-7（F-23）: `prefer` と `skip` に同じ種類を書いたチャンネル、知らない種類を書いたチャンネルを、`StationValidator` と yorisoi-console の確認の仕組みが拒む
8. AC-8（F-17・F-18）: 審査用の見本で AI に話させると、六曜で何かを勧めたり避けさせたりせず、記念日では定めた団体を添え、地域ごとの行事では地域を添え、渡した日付を言い換えない
9. AC-9（F-40・F-41）: 入れたばかりのアプリを Wi-Fi につなぐと、散歩をしなくても今の季節の曲が端末に入り、設定に曲の数が出る
10. AC-10（F-42）: 秋の日付で 30 分の経路を流すと、最初の雑談で季節の歌が流れる
11. AC-11（F-43）: AI を使わない設定でも、黙る時間（REQ-NEARBY-TALK D-7）が過ぎると定型の前置きのあとに歌が流れる
12. AC-12（F-44）: 前の形（`spot,revisit,milestone,rest,start,finish`）で保存した出来事の変更があっても、雑談・季節の歌・暦が出る
13. AC-13: 実機で 30 分ほど歩き、暦の雑談が自然に聞こえ（知識の披露や占いに聞こえない）、季節の歌が 1 回流れると開発者が感じる

## 用語定義

| 用語 | 意味 |
|---|---|
| 暦の事実 | `kit-calendar` が返す、その日に話せる暦の 1 件（`KoyomiFact`） |
| 確かさの種類 | 暦の事実が、天文・法律で決まるか、言い伝えか、定めた人がいるか、地域で違うか。話し方を決める（F-17） |
| 黄経 | 地球から見た太陽の位置の角度。春分点を 0° とする。二十四節気は 15° ごと |
| 朔・望 | 新月・満月 |
| 中気 | 二十四節気のうち、春分・穀雨・小満などの 12 個。旧暦の月を決めるのに使う |
| 暦要項 | 国立天文台が毎年 2 月に官報で発表する、翌年の暦（二十四節気・雑節・朔望・国民の祝日など） |

## 制約

| 種類 | 内容 | 本書での扱い |
|---|---|---|
| 国民の祝日に関する法律 | 祝日・振替休日・国民の休日を定める。春分の日・秋分の日は前年の暦要項で決まる | 決まりで計算し、法律が変わった年・暦要項と食い違う年は上書きの表で直す（F-5、D-2） |
| 著作権 | 七十二候の名前・暦の日付は事実で、著作物ではない。記念日の由来の説明文は書いた人の著作物になりうる | 説明の文は運営が書く。資料の文を写さない（D-5） |
| チャンネルの審査基準 | 移動と関係のない話題（占いなど）を中心にしない（[channel-review](../policies/channel-review.md)） | 六曜は言い伝えとして一言触れるだけにし、占いにしない（D-4、F-17） |

## 未決事項・リスク

| ID | 内容 | 対応 |
|---|---|---|
| U-1 | アプリ利用者が暦の種類を選ぶ設定（例:「六曜を話さない」）を置くか。利用者は絞ることだけできる（MATERIALS D-37 ②） | 実機で要望が出たら決める |
| U-2 | 散歩の始まり・区切りの話しかけでも暦に触れるか | 暦の雑談を実機で確かめてから |
| R-1 | 計算の誤差（1 分ほど）で、真夜中のすぐ前後の節気・朔の日付が 1 日ずれる。JitPack の配布が止まる、または中身が変わる | 暦要項と照らすテスト（AC-1）。ずれる年は上書きの表。版を固定し、取れなくなったら源コード（MIT）を写す |
| R-2 | 記念日・地域ごとの行事の表の誤り（団体・地域・日付の取り違え） | 各行に確かめた資料を残す（F-6）。知らせを受けたらアプリの更新で直す |
| R-3 | 六曜に触れることへの苦情 | 言い伝えとしてだけ話す（F-17）。チャンネルが外せる（F-21）。苦情が多ければ既定で外す |
| R-4 | AI が、渡した説明にない由来や言い伝えを足す | F-18 で頼む。審査の見本で確かめる（AC-8）。直らなければプロンプトを直す |
| R-5 | 話題が 1 つ増え、ほかの話題（見どころ・チャンネルの話題）の番が遠くなる | 実機の記録で話題の偏りを見る。必要なら暦を 1 回の散歩で 2 回までにする |
| R-6 | 旧暦の月の決め方（中気を含む月の名をとる）では、2033 年の秋から 2034 年の春の月が決まらない（2033 年問題） | `Lunisolar` は 2033 年より前の日付で使う。2033 年までに、暦の団体などが示した決め方を上書きの表で入れる |
