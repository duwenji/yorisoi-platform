## 目的・背景

語りの話題は、スポットの地図データ（OSM・Wikidata）、暦、天気、素材（スタジオ・一言）からできています。このうち「今日、近くで何が起きているか」を運んでいるのはスタジオだけで、素材提供者が自分で出さなければ届きません。祭り・朝市・展示・ライトアップのような地域の催しは、通りがかった人が知れば立ち寄れるのに、多くは自治体のサイトに載っているだけです。

自治体は、デジタル庁の「自治体標準オープンデータセット」の 1 つとして「イベント一覧」を公開しています。項目は全国で共通で、イベント名・開始日・終了日・開始時間・終了時間・場所名称・住所が必須、緯度経度・概要・URL は任意です。ライセンスはほとんどが CC BY 4.0（出典の表示が要る）で、一部が公共データ利用規約（PDL1.0）です。

本書は、これを運営が自動で取り込み、両アプリで「近くで今日ある催し」として話す要件です。REQ-KOYOMI が非スコープにした「日付で動くきっかけ（自治体のイベントの要件で検討する）」のうち、自治体の公開データの部分を受け持ちます。

### 公開データの実態（2026-11-16 に確かめたこと）

| 確かめたこと | 結果 |
|---|---|
| 全国をまとめて取れる API | ない。自治体ごとに CSV を、BODIK・東京都のオープンデータカタログ・自治体ごとのポータルなどに置いている。BODIK・東京都のカタログは CKAN の API で探せる |
| 垂水市（BODIK、7 件） | 日付が「4月下旬」「11月第１日曜日」のような文字。緯度経度はすべて空。中身は毎年の祭り。項目名は古い版（`住所` など） |
| 江東区（東京都のカタログ、337 件） | 323 件に緯度経度がある。日付の書き方がばらばら（`2025-10-..`・`2025/9/..`）。大半が講座・研修・相談会。最後の行は 2026 年 3 月で、更新が止まっている |

このため、取り込んだ行のうち、話してよいものはかなり少なくなる見込みです。本書は、どの行を残すかの決まり（F-7〜F-16）を中心に定めます。

## スコープ・非スコープ

### スコープ
- 取り込みのバッチ（yorisoi-console）: カタログからイベント一覧を探す、毎日取る、行を読み直す・選ぶ・位置を求める、タイルにして配る、運営に結果を知らせる
- 配信の契約: スポットのタイルの配信に `events` の層を足す（API-SPOT-TILES の変更）
- platform: タイルの `events` の層を取る部品、チャンネルの `talk.events` に `localEvent` を足す（core-format・API-CHANNEL-PACKAGE）
- 両アプリ: 雑談の話題「近くの催し」。SanpoGuide は予告も。話し方の固定部分、記録、出典の表示
- 文書の追従: プライバシーポリシー・利用者の手引き・出典の表示・技術チュートリアル

### 非スコープ
- 自治体標準オープンデータセットの形でない催しの情報（自治体・観光協会のサイトの記事、RSS、催しの案内サイト）。ページから読み取ることはしない
- Wikidata の祭りの項目（毎年の時期の分かる恒例の祭り）を話題にすること（U-2）
- 画面に催しを出すこと（地図の印・一覧）。話すだけ（U-3）
- 申し込みの要る催しの案内、料金・申し込み方法を話すこと
- チャンネルが独自の暦（寺の縁日・地域の祭りなど）を持つこと（REQ-KOYOMI の非スコープのまま）
- 催しを AI の審査済みの根拠（API-MATERIALS）にすること
- アプリ利用者が催しの種類を選ぶ設定（U-4）

## 方針・決定事項

| No. | 決定 | 理由 |
|---|---|---|
| D-1 | 催しは、運営のバッチが自治体の公開データから自動で取り込む。自治体・観光協会に、運営への登録や入力を頼まない | 開発者の決定（2026-11-16）。すでに公開されているデータを使うので、出す側の手間が増えない。提供者が自分で出したいときはスタジオがある |
| D-2 | 取り込む自治体は、運営が選ばず、カタログを探して見つかったものすべてにする。ただし、運営は止める一覧（データセット単位）で外せる（F-5） | 開発者の決定（2026-11-16）。運営は当面 1 人で、自治体ごとに確かめる手間をかけられない。質の悪い行は、行ごとの決まり（F-7〜F-16）で落とす |
| D-3 | 催しは「今の状況」として扱う。暦・天気・スポットの地図データと同じく、アプリが AI に渡し、審査済みの根拠（API-MATERIALS）には入れない | 開発者の決定（2026-11-16）。運営もチャンネル提供者も中身を審査していない。素材提供者もいない（MATERIALS D-2）。話し方はアプリの固定部分が受け持つ（AI-ROLES H-7） |
| D-4 | 配り方は、スポットのタイルと同じ配信（S3＋CloudFront、geohash 5 桁）に `events` の層を足す。作り直しは毎日。アプリは位置を送らない | 端末から運営へ送るものが増えない（API-SPOT-TILES ST-7）。催しは日の単位で変わるので、週 1 回のスポットのタイルとは別に毎日作る |
| D-5 | タイルに入れるのは、今日から 7 日先までに開かれる行だけにする | 話すのは今日の催しだけだが、端末が圏外でも数日は使えるようにする。過去の行・遠い先の行を配らない |
| D-6 | 残すのは、通りがかりで立ち寄れる催しだけ。祭り・市・展示・花火・ライトアップなど。講座・研修・相談・検診・説明会、申し込みや定員のあるもの、Web 開催は外す。分け方はバッチの決まり（F-10〜F-12）で行い、AI には分けさせない | 開発者の決定（2026-11-16）。江東区のデータの大半は講座・研修で、通りがかりの人には関係がない。決まりで分ければ、なぜ残ったか・外れたかを運営が確かめられる |
| D-7 | 日付は、日まで分かるものだけを使う。「4月下旬」「毎年8月」のような行は外す | 開発者の決定（2026-11-16）。誤った日に「今日あります」と話さない |
| D-8 | 緯度経度のない行・あやしい行は、場所名称をスポットのタイルの名前と突き合わせ、なければ住所から位置を求める（ジオコーディング）。位置の確かさを「地点」「町のあたり」に分け、確かめられない行は外す | 開発者の決定（2026-11-16）。垂水市のように緯度経度のない自治体が多い。位置の確かさで話し方を変え（F-30）、町のあたりしか分からないものを「この先 300 m」とは言わない |
| D-9 | 住所から位置を求めるのは、デジタル庁のアドレス・ベース・レジストリと、その住所照合の道具（abr-geocoder）をバッチの中で使う。外のジオコーディングのサービスには問い合わせない | 無料で、件数の上限や利用規約の制限がない。住所の表記ゆれに強い。データは CC BY 4.0 で、出典を示せば使える |
| D-10 | 話すときは、出どころを必ず添える（「〇〇市の公開情報では」）。開かれることは「予定」として話し、言い切らない。料金・申し込み・物を買うことを勧めない | CC BY の出典の表示を語りでも果たす。中止・変更をバッチは知りえない（R-1）。宣伝の扱いは AI-ROLES H-16 のまま、ほかの話題と区別しない |
| D-11 | 両アプリに入れる。予告（F-27）は SanpoGuide だけ。CycleGuide は雑談の話題だけ | REQ-NEARBY-TALK D-2 と同じ。CycleGuide は前方の見どころを既に先に話している |
| D-12 | チャンネルは `talk.events.localEvent` で止められる。書かなければ真 | 何について話すかは演出で、チャンネルの受け持ち（AI-ROLES H-1）。瞑想のような静かなチャンネルが切れるようにする。REQ-NEARBY-TALK D-16 と同じ形 |

## 機能要件

### カタログから探す（バッチ。週 1 回）
| ID | 要件 |
|---|---|
| F-1 | バッチは週 1 回、次のカタログを CKAN の API で探し、イベント一覧の候補を集める: BODIK、東京都のオープンデータカタログ、e-Gov データポータル。カタログの一覧と API の場所はバッチの設定に持ち、運営が足せる |
| F-2 | 候補は、題名に「イベント」を含み、CSV の資源を持つデータセット。同じ資源の URL は 1 つにまとめる |
| F-3 | 候補の CSV を取り、見出しの行に必須の列（イベント名・開始日・終了日・場所名称）がそろうものだけを取り込む一覧に入れる。自治体標準オープンデータセットの今の版の列名と、古い版の列名（`住所`・`都道府県コード又は市区町村コード` など）の両方を読む。文字コードは UTF-8（BOM の有無とも）と Shift_JIS を読む |
| F-4 | ライセンスが CC BY（2.1・4.0）・CC0・公共データ利用規約（PDL1.0）のものだけを取り込む。非営利に限るもの・改変を禁じるもの・ライセンスの分からないものは取り込まない。データセットのライセンス・自治体名・データセットの頁の URL を、取り込む一覧に残す |
| F-5 | 運営は、止める一覧（データセットの ID か資源の URL）を設定に持ち、止めたものは取り込まない。止めた理由を一緒に書く |

### 毎日取る・読み直す（バッチ。毎日）
| ID | 要件 |
|---|---|
| F-6 | バッチは毎日 4 時（日本時間）に、取り込む一覧の CSV をすべて取る。前の回の `ETag`・`Last-Modified` があれば付けて送り、変わっていないものは前の回の結果を使う。取れなかったものは、前の回の結果を 7 日まで使う |
| F-7 | 行ごとに、イベント名・開始日・終了日・開始時間・終了時間・場所名称・住所・緯度経度・概要（なければ説明）・開催条件と開始日時特記事項・URL（なければコンテンツ URL）・状態・イベント種類・キーワード・定員・参加申込方法・申込 URL・Web 開催を読む |
| F-8 | 日付は `YYYY-MM-DD`・`YYYY/M/D`・`YYYY年M月D日` の形（数字は全角も読む）を読む。それ以外は外す（D-7）。終了日がなければ開始日と同じとする。終了日が開始日より前・期間が 31 日を超えるものは外す |
| F-9 | 時刻は `hh:mm`・`hh:mm:ss`・Excel の日の割合（`0.75` は 18:00）を読む。読めなければ時刻なしとする |

### 選ぶ（バッチ）
| ID | 要件 |
|---|---|
| F-10 | 次のどれかに当たる行は外す（D-6）: 状態が「中止」「延期」「終了」/ Web 開催が「有」/ 定員・参加申込方法・申込 URL のどれかがある / イベント名・イベント種類に外す言葉（講座・教室・研修・相談・検診・健診・説明会・セミナー・募集・会議・面接・講習・訓練 など） |
| F-11 | 外れなかった行のうち、イベント名・イベント種類・キーワード・タグに残す言葉（祭・まつり・フェスタ・フェス・市（いち）・朝市・マルシェ・縁日・花火・展・展示・ライトアップ・イルミネーション・コンサート・演奏・パレード・踊り・神輿・山車・見ごろ・公開 など）があるものだけを残す |
| F-12 | 外す言葉と残す言葉の一覧はバッチの設定に持ち、運営が直せる。言葉ごとに、例と、外した・残した件数を結果に出す（F-21） |

### 位置（バッチ）
| ID | 要件 |
|---|---|
| F-13 | 緯度経度があり、日本の範囲にあり、所在地の市区町村（所在地の団体コード、なければ自治体の団体コード）の行政区域から 1 km より離れていなければ、その位置を「地点」として使う |
| F-14 | F-13 で決まらなければ、場所名称を、その市区町村の範囲にあるスポットのタイルのスポット・施設の名前と突き合わせる。名前が同じ（空白・括弧の中・「市立」「町立」などの前置きを除いて同じ）ものが 1 つだけなら、その位置を「地点」として使う |
| F-15 | F-14 で決まらなければ、住所（所在地_連結表記、古い版は住所）を abr-geocoder で照合する（D-9）。番地・住居表示まで合えば「地点」、町字までなら「町のあたり」とし、町字の代表点を使う。市区町村までしか合わないもの・照合できないものは外す |
| F-16 | 複数の会場を書いた行（場所名称に「ほか」「他」「各所」を含むもの、住所が複数あるもの）は、位置が決まっても「町のあたり」とする |

### タイル（API-SPOT-TILES の変更）
| ID | 要件 |
|---|---|
| F-17 | 配信に `GET {base}/v1/events/{geohash}.json` を足す。中身は、そのタイルに位置がある催しのうち、今日から 7 日先までに開かれるもの（D-5）。催しのないタイルは置かない（404） |
| F-18 | 催しの項目: `id`（自治体の団体コードと行の ID、なければ名前・日付・位置から作る）、`name`、`startDate`・`endDate`、`startTime`・`endTime`（あれば）、`venue`（場所名称）、`lat`・`lon`、`precision`（`point` か `area`）、`area`（`area` のときの町字の名前）、`summary`（概要か説明の先頭、120 字まで）、`conditions`（開催条件・開始日時特記事項。80 字まで）、`url`、`source`（自治体名・データセットの頁の URL・ライセンス） |
| F-19 | タイルの `license` は層ごとに持ち、`events` は出どころのライセンスの一覧にする。`LICENSE.txt` に、使った自治体のデータセットの名前・頁の URL・ライセンスと、「運営が選び、位置を求め、形を変えた」ことを書く |
| F-20 | 同じ催しが複数の行・複数のデータセットにあるとき（名前・日付が同じで位置が 200 m 以内）は 1 件にまとめ、`precision` が `point` のほうを残す |

### アプリ（両アプリ。platform の部品）
| ID | 要件 |
|---|---|
| F-23 | 散歩・走行の間、スポットのタイルと同じ取り方（今いるタイルとまわりの 8 枚）で `events` の層を取り、端末に残す。残したものは日付が変わったら取り直す。取れなくても、残したもので続ける |
| F-24 | 「近くの催し」は、今日開かれていて（終了時刻があれば、まだ終わっていない）、今いる場所（CycleGuide は前方の探す中心）から 1 km 以内のもの。今回の散歩・走行で既に話した催しは除く |

### 話す（両アプリ）
| ID | 要件 |
|---|---|
| F-26 | 雑談の話題（REQ-NEARBY-TALK F-15）に「近くの催し」を足す。近くの催しがあるときは、ほかの話題より先に選ぶ。1 つの催しは 1 回の散歩・走行で 1 回まで |
| F-27 | SanpoGuide では、歩いているとき、進む向きの前 300 m 以内に `precision` が `point` の今日の催しの会場があれば予告する。予告の決まり（REQ-NEARBY-TALK F-10〜F-13: スポットの話の間隔・1 回まで・静かなら出さない）に従う。AI がなければ定型の文（「〇〇市の公開情報では、この先の〇〇で、今日〇〇が開かれる予定です。」）で出す |
| F-28 | AI には、催しの名前・日付・時刻（あれば）・会場・`precision`（`area` なら町字の名前）・距離と方角（`point` のときだけ）・概要・開催条件・出どころの自治体名を渡す |

| F-30 | `precision` が `area` の催しは、「〇〇町のあたりで」と言い、距離・方角を言わない。予告にしない |
| F-31 | 長さは雑談・予告と同じ（1〜2 文・80 字以内。CycleGuide は今の雑談の上限） |
| F-32 | 話した催しは、散歩・走行の記録（開発者モードの詳しい記録を含む）に、催しの `id`・名前・出どころとともに残す |
| F-33 | 両アプリのプロンプトの版を上げ、正解ファイルと審査用の見本に、近くの催しの雑談（`point`・`area`）と予告を足す |

### 出典と文書
| ID | 要件 |
|---|---|
| F-34 | 両アプリの出典の表示（設定画面）に「自治体のオープンデータ（イベント一覧。各自治体、CC BY 4.0 ほか）を運営が加工」と、`LICENSE.txt` へのリンクを足す |
| F-35 | プライバシーポリシー・利用者の手引き・運営の手引き（止める一覧の扱い）・技術チュートリアルを追従させる |

## 非機能要件

| ID | 要件 |
|---|---|
| N-1 | プライバシー: アプリが外へ送るものは、`events` の層の URL（層とタイルの番号）だけ増える。位置・インストール ID は送らない（API-SPOT-TILES ST-7） |
| N-2 | 新しさ: 自治体が直した催しは、翌朝のタイルに入る。タイルの中身が変わらなければ `ETag` も変わらない |
| N-3 | バッチの時間: 毎日の取り込みは 30 分以内、週 1 回の探しを含む日は 60 分以内 |
| N-4 | 大きさ: `events` の層の 1 枚は gzip 後 50 KB 以内を目安にする |
| N-5 | 費用: 増えるのは月 1 USD 以内を目安にする（バッチの時間、アドレス・ベース・レジストリを置く S3、配信の転送） |
| N-6 | 礼儀: カタログと自治体のサーバーには、同じ相手へ同時に 1 本まで、間を 1 秒以上あけて送る。`User-Agent` に運営のバッチであることと問い合わせ先の URL を書く |

## 受入条件

1. AC-1（F-1〜F-4）: 開発用で週 1 回の探しを流すと、BODIK と東京都のカタログから取り込む一覧ができ、ライセンスが合わないデータセットが入っていない
2. AC-2（F-8・F-9）: 「4月下旬」「11月第１日曜日」の行が外れ、`2025/9/3`・`２０２６年１２月１日`・`0.75` が正しく読める（バッチのテスト）
3. AC-3（F-10〜F-12）: 江東区のデータで、講座・研修・相談会と、定員・申し込みのある行がすべて外れる。祭り・朝市・展示の見本の行が残る（バッチのテスト）
4. AC-4（F-13〜F-16）: 緯度経度のない垂水市の見本の行で、スポットのタイルに同じ名前の公園がある行が `point` に、住所が町字までの行が `area` に、市区町村までの行が外れる（バッチのテスト）
5. AC-5（F-17〜F-20）: 作った `events` のタイルが Schema に合い、今日から 7 日先までの催しだけが入り、`LICENSE.txt` に使ったデータセットがすべて載る
6. AC-6（F-21・F-22）: 運営に届くまとめに、データセットごとの件数と、新しく見つかったデータセットが出る
7. AC-7（F-24〜F-27）: 開催中の催しの会場の近くを歩くと、雑談か予告で 1 回だけ話され、2 回目は話されない。`talk.events.localEvent` が偽のチャンネルでは話されない（テスト）
8. AC-8（F-29・F-30）: 審査用の見本で AI に話させると、自治体名を添え、「予定」と言い、日付・時刻を言い換えず、料金・申し込みを勧めない。`area` の催しで距離・方角を言わない
9. AC-9（N-1）: 散歩の間の通信を見て、`events` の層の要求に位置・インストール ID が入っていない
10. AC-10（N-3・N-4）: 日本全体で流し、データセットの数・残った行の数・時間・タイルの大きさを記録し、目安に収まる
11. AC-11: 実機で催しのある日に散歩・走行をし、話が自然で、出どころが分かり、宣伝に聞こえないと開発者が感じる

## 用語定義
| 用語 | 意味 |
|---|---|
| 自治体標準オープンデータセット | デジタル庁が定めた、自治体が公開するデータの共通の形。「イベント一覧」はその 1 つ |
| カタログ | オープンデータの一覧を載せたサイト（BODIK・東京都のオープンデータカタログ・e-Gov データポータル）。CKAN の API で探せる |
| 取り込む一覧 | バッチが探して決めた、毎日取るデータセット（CSV）の一覧 |
| 止める一覧 | 運営が決めた、取り込まないデータセットの一覧（F-5） |
| 近くの催し | 今日開かれていて、1 km 以内にある催し（F-24） |
| 位置の確かさ | `point`（会場の地点が分かる）か `area`（町のあたりまでしか分からない） |
| アドレス・ベース・レジストリ | デジタル庁が整備する住所の基礎データ。abr-geocoder はそれで住所を照合する道具 |

## 制約
| 種類 | 内容 | 本書での扱い |
|---|---|---|
| CC BY 4.0・PDL1.0 | 出典を示す。加工したことを示す | タイルの `source`・`LICENSE.txt`・アプリの出典の表示・語りで自治体名を添える（F-19・F-29・F-34） |
| 公開データの質 | 自治体ごとに、日付・位置・更新の頻度がばらばら | 行ごとの決まりで落とす（F-8〜F-16）。結果を運営に知らせる（F-21） |
| 中止・変更 | 公開データは天候による中止などをすぐには反映しない | 「予定」として話す（D-10）。状態が「中止」の行は外す（F-10） |
| 運営の人数 | 当面 1 人 | 自治体ごとの確かめはせず、止める一覧と週 1 回のまとめで見る（D-2・F-22） |

| No. | 内容 | 決める時期 |

| U-2 | Wikidata の祭りの項目（毎年の時期・場所が分かるもの）を、「この時期に〇〇の祭りがあります」の話題に足すか | 本書の版を使ってから |

| U-4 | アプリ利用者が催しの話をやめる・種類を選ぶ設定を置くか | 本書の版を使ってから |

### リスク
| No. | リスク | 対策 |
|---|---|---|
| R-1 | 中止・変更になった催しを「今日あります」と話す | 「予定」として話す（D-10）。状態が「中止」「延期」の行は外す。通報（AI-ROLES H-11）で知らせを受けたら止める一覧に入れる |
| R-2 | 位置を誤って求め、違う場所の話をする | 位置を確かめる順番と確かさの分け方（F-13〜F-16）。`area` は距離・方角を言わない |
| R-3 | 残す言葉の決まりが粗く、通りがかりに関係のない催しや、店の売り出しが混ざる | 週 1 回のまとめで、言葉ごとの件数を見て直す（F-12・F-22）。話し方で買い物を勧めない（F-29） |
| R-4 | 使える行が少なく、ほとんどの場所で話題にならない | 日本全体の件数を AC-10 で確かめる。少なければ U-1・U-2 を先に検討する |
| R-5 | カタログの API・CSV の置き場所が変わり、取れなくなる | 7 日まで前の回の結果を使い（F-6）、取れないことをまとめで知らせる（F-21） |
| R-6 | ライセンスの読み違いで、使えないデータを配る | ライセンスの値を許す一覧で判定し（F-4）、データセットの頁の URL を残す |
